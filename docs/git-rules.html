처음 한 번만 한다. 저장소 담당자 설정이 끝난 뒤 팀원이 받는다.

SETUP
저장소 처음 받기
팀원 각자 1회
  1. GitHub 메일 또는 알림에서 저장소 초대(Collaborator)를 수락한다.
  2. 저장소를 받는다. 
    git clone https://github.com/wkuMyeungsu/physical-ai-teamproject_01.git
cd physical-ai-teamproject_01
  3. 작성자 정보와 pull 방식을 설정한다. 
    git config user.name "이름"
git config user.email "GitHub 계정 이메일"
git config pull.rebase false
  4. 내 서비스 브랜치로 이동해 확인한다. 
    git switch base/dashboard        # 원격 브랜치를 따라가는 로컬 브랜치가 생긴다
git branch -a                   # main, dev, base/* 가 보이면 완료
  5. 내 서비스 컨테이너가 뜨는지 확인한다. 작업은 services/<서비스>/ 폴더 안에서만 한다. 
    docker compose up --build dashboard   # 내 서비스 이름. 이 폴더에 Dockerfile이 있어야 한다
서비스폴더기준 브랜치컨테이너 주소담당
dashboardservices/dashboard/base/dashboardhttp://dashboard:8000명수
frame-captureservices/frame-capture/base/frame-capturehttp://frame-capture:8001대희
ocr-extractservices/ocr-extract/base/ocr-extracthttp://ocr-extract:8002도은
vector-storeservices/vector-store/base/vector-storehttp://vector-store:8003진아
rag-chatservices/rag-chat/base/rag-chathttp://rag-chat:8004우진
ADMIN
저장소 구성
저장소 담당자 1회 · SETUP보다 먼저
  1. 브랜치를 만들어 올린다. 
    git switch main
git switch -c dev && git push -u origin dev
for s in dashboard frame-capture ocr-extract vector-store rag-chat; do
  git branch base/$s dev && git push -u origin base/$s
done
  2. GitHub에서 설정한다.
    GitHub 설정값
    Settings → Collaborators팀원 GitHub 계정 초대
    Settings → Branches → 보호 규칙 대상main, dev
    Require a pull request before merging켬 · 승인 1명
    Allow force pushes / Allow deletions끔
    Settings → General → Pull RequestsAllow merge commits만 켬

팀원 누구나. 기능 하나마다 TASK 0 → TASK 1을 반복한다.

TASK 0
기능 브랜치 만들기
기능 시작 시
git switch base/dashboard && git pull
git switch -c feature/dashboard-login-button
# 작업은 services/dashboard/ 안에서만, 실행은 docker compose up --build dashboard
# git add services/dashboard/<파일> → git commit
git push -u origin feature/dashboard-login-button
TASK 1
기능 → 서비스 (PR)
기능 하나 끝날 때마다
  1. 서비스 브랜치의 최신 내용을 받아와 충돌을 미리 푼다. 
    git pull origin base/dashboard
git push
  2. GitHub에서 PR 생성: base base/dashboard ← compare feature/dashboard-login-button
    경고WARNING

    PR 화면의 base 기본값은 main이다. 반드시 base/<서비스>로 바꾼 뒤 만든다.

  3. 리뷰어 1명 승인 → Create a merge commit → Delete branch
  4. 로컬 정리 
    git switch base/dashboard && git pull
git branch -d feature/dashboard-login-button
주의CAUTION

충돌 시: 파일에서 <<<<<<< ~ >>>>>>> 정리 → git add → git commit. 포기하려면 git merge --abort.

서비스 담당자와 저장소 담당자. TASK 2 → 3 → 4 순서로 한다.

TASK 2
서비스 → dev (PR)
서비스 담당자 · 주 1회 또는 기능 2~3개마다
  1. dev의 최신 내용을 받아온다. 충돌은 여기서 푼다. 
    git switch base/dashboard && git pull
git pull origin dev
git push
  2. GitHub에서 PR 생성: base dev ← compare base/dashboard
  3. 리뷰어 1명 승인 → Create a merge commit
주의CAUTION

병합 후 Delete branch를 누르지 않는다. base/*는 계속 쓰는 브랜치다.

TASK 3
dev → main (PR)
저장소 담당자 · dev 테스트 통과 후
  1. dev를 받아 실행·테스트한다. 
    git switch dev && git pull
  2. GitHub에서 PR 생성: base main ← compare dev
  3. 승인 → Create a merge commit
경고WARNING

dev에서 문제가 나오면 main에 올리지 않는다. fix/* 브랜치로 고친 뒤 TASK 1부터 다시.

TASK 4
dev 받아오기
서비스 담당자 · TASK 3 직후
git switch base/dashboard && git pull
git pull origin dev
git push

이후 팀원은 다시 작업할 때 탭의 TASK 0부터 시작한다.

참고NOTE

GitHub이 "dev is behind main"이라고 표시해도 된다. 차이는 병합 커밋뿐이라 다음 dev → main PR에 영향이 없다.

작업 위치 WORKSPACE

단위서비스 1개 = 담당자 1명 = services/<서비스>/ 폴더 1개 = 컨테이너 1개 = base/<서비스> 브랜치 1개
작업 범위코드·Dockerfile·의존성 파일 모두 내 서비스 폴더 안에만 둔다. 다른 서비스 폴더는 읽기만 한다.
실행내 폴더의 Dockerfile로 컨테이너를 만들어 실행한다. 저장소 루트에서 docker compose up --build <서비스>. 호스트 PC에 직접 설치해 돌리지 않는다.
서비스 간 호출컨테이너 주소로 HTTP 호출 (예: http://ocr-extract:8002). 컨테이너 안의 localhost는 자기 자신이다. 다른 서비스 코드를 import하지 않는다.
공용 파일docker-compose.yml, README.md, AGENTS.md, docs/는 팀장과 상의 후 바꾼다.
AI 도구저장소 루트의 AGENTS.md(Claude Code는 CLAUDE.md)에 같은 규칙이 있다. AI가 내 서비스 폴더 밖을 고치려 하면 멈춘다.

PR 병합 방식Create a merge commit 만 사용. (Squash, Rebase 금지)

금지 사항 PROHIBITED

경고WARNING
  • main, dev에 직접 push — 모든 변경은 PR로
  • base/*에 직접 작업 커밋 — 기능은 feature/*에서
  • 내 서비스 폴더(services/<서비스>/) 밖의 파일 수정 — 공용 파일은 팀장과 상의 후
  • 호스트 PC에 직접 의존성 설치·실행 — 컨테이너로 실행
  • git push --force
  • 다른 사람의 브랜치에 push
  • 비밀키, 토큰, .env 커밋 — 올라갔다면 즉시 키를 폐기·재발급

기능이 서비스에 모이고 dev → main으로 올라간 뒤 같은 순서를 반복하는 모습. 그래프의 번호는 TASK 번호다.
